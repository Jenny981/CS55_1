# 系统意义、价值与边界

## 要解决的问题
审核者拿到成片和不同形式的制作材料后，需要逐一查找对应画面、核对顺序、检查来源记录，并区分信息缺失与真正矛盾。这项工作量很大，单一相似度分数又无法解释材料如何支持成片。

## 系统提供的价值
- **以Final组织证据：**从成片采样帧出发寻找Storyboard或Animatic支持，明确哪些材料未提交。
- **缩小人工查找范围：**展示候选、Panel描述和可修改选择，让审核者集中处理不确定项，不必手工遍历所有组合。
- **让矛盾可见：**全局检索独立于Correspondence声明，保留范围外匹配及证据索引回退，不通过预先限制搜索隐藏偏离。
- **多方面解释支持情况：**视觉覆盖、顺序、声明符合度、来源和时间戳分别回答不同问题，避免一个总分掩盖证据短板。
- **让判断可追踪：**记录自动或人工来源、观察值、得分条件和原因，输出可复查JSON。
- **保证实现一致：**Notebook、CLI与界面使用共享Python模块，减少各入口算法重复和结果口径分歧。

## 使用对象与用途
学生和制作团队可以组织提交材料；导师、客户可以定位需要解释的内容；开发者可以复现选择并分析检索问题。核心用途是辅助证据审核和可解释汇报。

## 可以说到什么程度
已选匹配表示在当前规则下存在候选支持；顺序异常表示已选索引存在排序矛盾；Correspondence偏离表示检索结果与声明不一致；Provenance和时间戳描述可观察的来源支持与冲突。各项都需要结合制作背景解释。

## 不能扩大成什么结论
系统不认证作者身份，不保证识别AI生成，不凭低分判断造假，也不能仅凭本次计算的哈希证明历史上未修改。自动选择仍是暂定结果；阈值和评分权重是待验证的设计规则。

降低人工工作量、提高匹配效果是目标，不能在没有实验时当作已证明成果。应使用独立标注的留出样本，统计Top-1正确率、Top-K召回、拒绝匹配是否合理、人工修正比例和每份材料耗时；方法比较必须使用相同数据、配置与审核预算。

## 后续改进优先级
优先改善Panel与文字准备、模糊匹配检查、接受规则的独立评估、源工程关联验证以及证据来源解释。不要仅为了覆盖率更高而强行接受更多候选。
